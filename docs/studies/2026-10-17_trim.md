# Trim pass: cutting dead code and art (Oct 17, on 1.41.56)

## For Jeremy, in short

Jeremy asked to "optimize the game ... as much as possible. cut out unnecessary stuff". This pass removes leftovers only, and nothing changes on screen. Each screen was screenshotted before and after the cut (72 scenes) and the pictures match pixel for pixel. Every automated check still passes.

**What was cut**
- **Stylesheet:** 31.7 KB of rules that could never apply. Some were for classes the game no longer uses: the old toasts, the old shield bar, the old depth card, the old shrine hold button, the HUD columns and the old loot pips. Others were settings that a later rule always overrode, and 25 animations were either defined twice or used by nothing.
- **Code:** a few functions nothing calls anymore. One was the old "shrine result" pop-up. One was a wood-grain texture generator whose output nothing used. It also ran a 65,000-pixel loop and three image encodes every time the game loaded, so removing it also saves work on load.
- **Art:** an unused cat silhouette. The logo picture is only used by the rulebook, so it stays in the source for the rulebook but is no longer packed into the game.
- **Build:** the shipped stylesheet no longer includes the developer comments. They stay in the source.

**One real bug found, not fixed (it would change behavior):** the web app build (`dist/web/`, the Netlify version) has **no music**. `build.js` assembles the web page from `[data, assets, logic, depth, render, main]` and leaves out `music.js`. The game's music calls are all guarded with `typeof musicUpdate==='function'`, so nothing errors; the music is just silently missing. Only the single-file preview has music. The fix is one word: add `music` after `render` in `webScriptParts`. This needs your OK because it changes what players hear.

## Details

### CSS (scripted, postcss; script kept in the trim scratch dir, not in the repo)
1. **Dead selectors (88 selectors, 69 whole rules).** A class or id counts as dead only if its name appears nowhere in src JS/HTML or build.js, comments included, so a class mentioned only in a comment is kept. Names built at run time were handled too. Any prefix followed by `${` or `'+` counts as used. Four prefixes are generic, and their real values were checked by hand: `bar-`+killHint.state is close/kill/overkill, `rb-${tone|dir}`, `loot-${i}` and `fo-${sel}` is player/enemy. Selectors inside `:not()` were never judged. Removed classes include: char-icon-wrap/img, path-chip, chip-num, path-strip-col, key-title, camp-subhint, toast/toast-good/toast-bad, loot-sunray-wheel-2, loot-chest-label, loot-art-thumb, boon-none-item, relic-origin, run-total, faces-dots/face-dot, fo-has-quests, fo-tight, fo-hud-col/-l/-r, rb-streak (+s1/s2), rb-combat-pos, title-btn, loot-pips, bar-shield, depth-card/depth-head/-text, title-badge-name, q-mark, pocket-open, shrine-hold-fill/-label.
2. **Overridden declarations (431).** A declaration was removed only when every selector of its rule has a later rule with the identical selector, in the same @media context, that sets the same property, or its shorthand (margin, padding, inset, gap, overflow, background, transition, animation, border-radius), with equal or higher `!important`. Two things were never touched. A later declaration in the same block was left alone, because it could be a fallback. A later value using features an older browser might drop was also left alone: dvh/svh, color-mix, oklch, `-webkit-`, fit-content and similar. 82 rules ended up empty and were removed.
3. **Keyframes:** 9 earlier duplicates, where the later definition wins (upgradeReady, zoneTwitch x2, zoneSoft, flip-tile, ability-convert-pulse, loot-chest-glow/-bob/-flip). There were also 16 keyframes nothing referenced after the cleanup (poke-jerk-kf, toast-sweep, enc-death-kf, fo-mon-death, rb-in-l/r/n, idle-twitch-p/e, idle-glint-p/e, quest-flicker, idle-move-e, zone-armed, zoneSoft, zonePulse). Each one was traced back to the overridden declaration that used to name it.
4. **Chrome CSS coverage** (CDP rule usage across all 72 scenes) was used as a cross-check, not as the cut list. 1055 of 1521 rules matched. Most of the 466 that never matched are hover, reduced-motion and mid-animation states that a still screenshot can't reach, so they were kept.

### JS
A scan of every top-level function/const in src/*.js, counting references across src/, tools/ (including tools/balance), sim.js, bugsearch.js and build.js with comments stripped, found only the 7 names above, plus `makeTextureTiles`. That function was called, but the three CSS variables it set (`--paper-tile-light`, `--paper-tile-med`, `--wood-tile`) are read nowhere. No commented-out code blocks were found. The only `actionCycle` code left is the deliberate old-save upgrade in `initEnemyTurnState`. The REVIVE_RULE 'one'/'half' branches are a decided test switch, so they were left in.

### Art
Every key in MONSTER_ART and LOOT_ART is the `name` of a live card, die or shrine, or a SHRINE_ART_STANDIN target, and every portrait array is used. There are no duplicate images. The art is already WebP, so it can't be shrunk losslessly.

  - splash, title, title with a saved run
  - setup (each origin, a locked origin, a second class, scrolled)

  - minions, a selected path, Skill armed, Swap and Reroll armed, the tokens modal, low HP with statuses, relics and the relics modal, room and boss callouts, the floor card, the debug class, the Back Pocket
  - loot: closed chest, open chest, overkill and the equip/swap pop-up

- Result: comparing the before and after builds pixel by pixel, nothing differs. 7 scenes showed differences at the default 150 ms settle (particles and image decode timing). The before build showed the same differences against itself. With a 2.5 s settle, before vs after is identical in all of them. In one scene (f3_bigboss2) a 137 px difference reproduced in every run. It was checked element by element: same layout boxes, same computed styles including ::before/::after, same img sources and canvas content. With a longer settle it disappears, so it was image-decode timing, not CSS.
- Tests: `node tools/check.js` all ok (sim 5, classes 25, wrap 12, ui 38, pathrender 8, trayfast 3, trayact 18, shrines 40), plus `node sim.js` twice more: all PASS.

## Quick performance notes (measured, not applied)
These were measured in a floor-1 fight, headless Chromium, desktop CPU, so a phone will be several times slower.
- Full `render()` takes about 14 ms. `renderGame()` alone is about 9 ms, and `decorateArch()` adds 2.6 ms on every full render because the arch SVG is rebuilt. Path taps already use the fast path (about 3.5 ms per tap).
- Every full render on game, camp and shrine screens also calls `maybeAutosave()`. That writes about 117 KB to localStorage (about 1.2 ms), of which about 20 KB is the tinted portrait as a data URL. Two possible fixes: save only at turn and room boundaries, or store the portrait as origin+index+tone and re-tint it on load.
- Shipping the JS without comments would save about another 74 KB (render.js 315 KB to 277 KB, logic.js 154 KB to 126 KB). It wasn't done because it needs a real parser, such as the global `typescript` package, which this build doesn't depend on today. It would also renumber the line numbers that error telemetry reports.
- The stylesheet still has many selectors defined 3 to 6 times. Merging them into one rule each would make it smaller and easier to edit. That reorders the cascade, though, so it should be a separate pass with the same screenshot check.
