### Real bugs

**B1. Boost tokens never apply (high impact, old: since the per-die playback of Sep 30).**
- *What I did:*
  - With the Scroll Dispenser: GIB token (x4), I opened Item, tapped "Use x4 Boost Token" and picked a single Hit 3, then pressed Go. I did this through the real UI.
  - I repeated it with Arcanist: token x4, then Boost x2 (x3), then Hit 2.
- *What happened:*
  - Hit 3: the preview counter showed 12, but the enemy lost 3 and the log said "Path dealt 3.0 damage." The token was spent.
  - Arcanist: the preview showed 24, but only 6 damage was dealt.
- *What should happen:* the damage dealt should match the preview (12 and 24).
- *Location:* `src/logic.js:1905` in `startTurnTransition()`. `S.pendingFreeBoost = 0;` runs *before* `computePathSteps(path)` and `computePathEffects(path)` (lines 1908-1909), and both read `S.pendingFreeBoost` for their starting multiplier.
- *Fix:* move the reset below line 1909, after both calls and before `runPlayerPathSteps`.
- *Worth checking after the fix:* whether any study assumed the token works (the shrine was rated with it).

**B2. Dungeoneer + FTLeporter: an edge-to-edge teleport counts as a wrap and loses its Teleport tag (low impact).**
- *What I did:* as a Dungeoneer holding FTLeporter, I made the path Pivot (0,0) then Hit 1 (3,3). That step is a teleport, not a wrap: the rows are 3 apart.
- *What happened:*
  - The step got `seamBonus` 1, so it dealt 2 damage and popped "+1 Wrap".
  - It got no `pivot_compass` "Teleport" tag, so the relic's gem never pops.
- *What should happen:* +0 damage and the Teleport tag. Only real wraps should count: same row for a step, one row apart for a Dodge or Pivot across the seam.
- *Location:*
  - `src/logic.js:95` (`applyClassToSteps`) counts any column difference of 3 as a wrap.
  - `src/logic.js:140` (the `pivot_compass` tag) skips any `adjWrapCols` pair.
- *Fix:* add an `isWrapStep(a,b,lastFaceType)` that repeats the `canSelect` wrap rule (`vb` virtual column + the face's own move rule). Use it in both places.

### Cosmetic nits
1. **The Arcanist's boosted Boost shows as x2 in two places.**
   - *Where:* the path coin tooltip (`src/render.js:1988`, `renderPathStrip` uses `getFaceForIdx`) shows "1. Boost 2" while the tray shows "Boost 3". The long-press tooltip on a die (`src/render.js:1963`) also shows the raw face.
   - *Fix:* wrap both in `classFace()`.
2. **The wrap path trail is drawn straight across the tray.** A wrap step's trail (`updatePathTrail`) is a straight line from column 3 to column 0, through the two middle dice, so it reads like an illegal step. This is old (Oct 12), but the wrap now carries damage. A short stub off each edge would read better.
3. **The "+1 Wrap" float overlaps the die's own badge.** It sits at 30% of the die's height, over the die's corner number and the trail. It is readable in the screenshot, but its "+" sits under the trail. Lifting it slightly above the die would fix it.
4. **Dead text in the Break Camp confirm** (`src/render.js` ~4407): the `S.campRested ? "You can't come back…"` branch can no longer show, because the modal now only opens when the fire is unused.
5. **New opt-ins re-send everything once** (`src/logic.js:259/266`): `setShareData(true)` doesn't set `dungeonScrambleUploadConfirm_v2`. So at the next launch, `resendUnconfirmedRuns` clears the sent list and queues every run again. The server skips the duplicates, so this only wastes requests. Fix: set the flag in `setShareData(true)`.
6. **The Boost token reads x4 for the Arcanist** (the class gets no +1 on it), since a token isn't a Boost die that is played. The class text says "Your Boosts are 1 stronger", so ask Jeremy whether the token should count. This is a design question, not a bug.
